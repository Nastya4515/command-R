# Рекомендуемый формат — предметная область 2: RAG

Это адаптация структуры пакета ВИНИТИ для RAG. Официальный архив-пример относится к предметной области 1; официальным шаблоном RAG данный файл не является. Состав предметных полей перенесён со страниц 8–9 файла `viniti_case_final.pdf`, правила проверки — со страницы 10. Условия кейса не меняются. Формат рекомендуется для машинного сопоставления результатов; он не вводит новое требование к участникам.

## Таблицы и ключи

| Файл | Сущность | Ключ внутри публикации |
|---|---|---|
| publications.csv | Библиография и решение о включении | publication_id |
| configurations.csv | Конфигурация RAG или сравниваемого baseline | config_id |
| datasets.csv | Набор данных, версия и разбиение | dataset_id |
| tasks.csv | Задача | task_id |
| experiments.csv | Протокол и условия эксперимента | experiment_id |
| results.csv | Одно значение одной метрики в одном эксперименте | result_id |
| issues.csv | Замечание проверки с привязкой к результатам | issue_id |

Во всех таблицах есть `publication_id`. Это имя PDF без расширения, например `D001` или `P090`. Другие идентификаторы уникальны **внутри публикации**. Результат связывает эксперимент, конфигурацию, набор и задачу. `duplicate_of` ссылается на `result_id` той же публикации; `issues.record_ids` содержит такие ссылки через `;`. Одинаковые имена моделей или датасетов не дают основания объединять разные эксперименты.

Поля `in_scope`, `exclusion_reason`, `duplicate_of`, `note` и поля таблицы замечаний — служебные соглашения формата. Они не добавляют предметных требований к условиям. Связь прибора с материалом из солнечной области для RAG не переносится.

## Общие правила

- UTF-8, разделитель — запятая, десятичный знак — точка. Кавычки и переводы строк экранируются по правилам CSV. Заголовки и порядок колонок приведены в пустых таблицах и `schema.json`.
- Пустая ячейка означает отсутствие сведений в публикации, а не ноль. Не использовать `NaN`, `null`, `unknown` вместо пропуска. Ноль сохраняется как `0`.
- Не достраивать версии моделей, параметры, шкалы и условия по известным настройкам библиотек или по другим статьям. Сохранять исходное обозначение; неоднозначность пояснять в `note`.
- `authors` и `record_ids` могут содержать списки через `;`. Ссылочные поля результата содержат один идентификатор.
- `source_page` — целый номер страницы **PDF**, с 1, а не печатная нумерация журнала.
- `source_fragment` — дословный фрагмент указанной страницы. Произвольную запись «таблица 3, строка X» следует помещать в `source_table` / `note`, если такой фразы в PDF нет. Не заменять цитату пересказом.
- Для графика или изображения допустим точный указатель `source_figure` и пояснение способа чтения в `note`. Автоматический поиск цитаты не подтверждает визуальное считывание; такой случай проверяют по изображению страницы.
- Пустые поля шаблона не являются разметкой со статусом `absent`. Не создавать декартово произведение всех метрик и конфигураций с искусственными отсутствующими значениями.

## Поля

### publications.csv

| Поле | Содержание |
|---|---|
| publication_id | Имя файла без `.pdf` |
| title | Название статьи |
| year | Год публикации |
| DOI | DOI, если известен из источника; иначе пусто |
| authors | Авторы через `;` |
| in_scope | `true` или `false` |
| exclusion_reason | Причина исключения, обязательна при `false`, при `true` пуста |

Строка нужна для каждого PDF проверяемого набора. Предметные границы: система находит сведения во внешней коллекции документов и использует контекст при формировании ответа; статья описывает конфигурацию и результаты оценки. Решение принимается по содержанию, а не по наличию слова RAG в заголовке. У исключённой публикации в остальных шести таблицах нет строк.

### configurations.csv

| Поле | Содержание |
|---|---|
| config_id | Идентификатор конфигурации |
| rag_variant | Название/вариант системы или baseline из статьи |
| retrieval_method | Способ поиска: исходная формулировка, например BM25, dense, hybrid |
| retriever_model | Название поисковой модели |
| embedding_model, embedding_version | Модель эмбеддингов и отдельно указанная версия |
| chunking_method | Способ сегментации |
| chunk_size, chunk_overlap | Размер и перекрытие, если указаны численно |
| chunk_unit | Единица сегмента: tokens, characters и т. п. по источнику |
| index_type, vector_store | Тип индекса и хранилище; одно не выводится из другого |
| top_k | Число извлекаемых элементов; не смешивать с k метрики |
| reranker_model | Модель повторного ранжирования |
| generator_model, generator_version | Генератор и явно указанная версия |
| prompt_strategy, context_strategy | Стратегия промпта и обращения с контекстом |
| note | Название строки таблицы, дополнительные параметры, неоднозначности и источник сведений |

Разные генераторы, ablation-варианты и настройки оформляются отдельными конфигурациями. Если параметр дан диапазоном, не подставлять среднее: числовое поле оставить пустым, исходный диапазон указать в `note`.

### datasets.csv и tasks.csv

`datasets.csv`: `dataset_id`, `dataset_name`, `dataset_version`, `language`, `data_split`, `scientific_domain`, `note`. Версия, язык, разбиение и область заполняются по статье. Разные версии или разбиения, участвующие в разных сравнениях, не сливаются.

`tasks.csv`: `task_id`, `task_type`, `note`. Например, тип задачи может быть указан как multi-hop question answering. Это пример записи, а не закрытый словарь. Связь задачи с набором фиксируется в `results.csv`.

### experiments.csv

| Поле | Содержание |
|---|---|
| experiment_id | Идентификатор эксперимента |
| evaluation_protocol | Протокол, условия оценки, способ расчёта и ограничения сравнения |
| baseline_name | Название сравниваемого baseline, если оно указано |
| hardware | Оборудование и количество устройств по статье |
| latency_ms | Задержка в миллисекундах при известной исходной единице; исходная запись — в note |
| tokens_per_query | Число токенов на запрос; общий расход не делить на запросы без установленного основания |
| sample_size | Размер оценочной выборки, не размер всего исходного датасета |
| note | Уточнения и место описания протокола |

Задержка и число токенов, зависящие от конфигурации, не должны ошибочно распространяться на все конфигурации одного эксперимента. Такие значения можно оформить отдельными результатами метрик с соответствующей связью, либо разделить эксперименты по условиям.

### results.csv

| Поле | Содержание |
|---|---|
| result_id | Идентификатор записи |
| experiment_id, config_id, dataset_id, task_id | Связи с таблицами той же публикации |
| metric_group | Группа показателей по смыслу источника; свободный текст |
| metric_name | Название метрики |
| metric_variant | Определение/вариант: например, token-level F1, macro, micro, judge-based |
| metric_direction | Рекомендуемые обозначения: `higher_is_better`, `lower_is_better`, `target`; неизвестное направление — пусто |
| metric_k | k для метрики @k, если применимо |
| metric_value, metric_unit | Нормализованное значение и единица, если нормализация обоснована |
| baseline_value | Значение baseline только для сопоставимых задачи, набора, определения метрики, шкалы и протокола |
| aggregation | Среднее, медиана и т. п. только при явном указании; это открытое поле |
| sample_size | Размер выборки для данного результата, если отличается или указан отдельно |
| raw_value, raw_unit | Исходная запись значения и единицы, включая знаки, диапазоны и обозначения |
| normalized_value, normalized_unit | Нормализованная пара; согласована с metric_value и metric_unit |
| result_origin | `primary` — результат, полученный в данной работе; `cited` — перенесённый из другой работы |
| cited_publication_id | Для `cited`: ссылка в статье, например `[12]` или `Lewis et al., 2020`; не внешний ключ к publications.csv |
| source_page, source_section, source_table, source_figure | Указатели на источник; номер страницы PDF обязателен для извлечённого значения |
| source_fragment | Дословная цитата, позволяющая найти значение; для таблицы допустима цитата строки с уточнением столбца в note |
| extraction_status | `extracted`, `present_not_extractable`, `absent` |
| duplicate_of | Идентификатор основной записи того же значения, повторно упомянутого в другом месте |
| note | Уточнение столбца/кривой, способ нормализации, неоднозначность |

`primary`/`cited` определяется происхождением числа. Результат чужого метода, заново воспроизведённый авторами, является `primary`; одно лишь название baseline не делает число цитируемым.

`present_not_extractable` используется, когда значение действительно обозначено, но достоверно извлечь его из доступного PDF нельзя (например, отсылка к отсутствующему supplementary). Это не замена непроделанной разметке. Значение с чёткой подписью на графике может быть `extracted` после визуальной проверки.

Повтор отличается местом извлечения и имеет собственный `result_id`. У основной записи `duplicate_of` пуст. Циклы, ссылки на себя и объединение разных экспериментов недопустимы. Если значения расходятся, сохраняются обе записи и создаётся замечание; разные числа не объявляются дублями.

Доли, проценты, BLEU/ROUGE и временные единицы не пересчитываются по одному только имени метрики. Нужна установленная шкала и единица. При нормализации сохраняется исходная запись. `NaN` и бесконечность не являются допустимыми числовыми ячейками; исходное обозначение сохраняют в raw_value и объясняют.

### issues.csv

`issue_id` — ключ замечания; `record_ids` — result_id через `;`; `check_name` — название правила; `description` — что не согласуется, с числами и условиями; `source_page`, `source_fragment` — место проверки.

Названия правил открытые. Рекомендуемые примеры: `metric_scale`, `metric_k`, `protocol_mismatch`, `normalization`, `contradiction`. Скрипт не заменяет содержательную проверку: выход за шкалу фиксируется как замечание, исходный результат не удаляется.

## Словари и проверка

Закрытые словари в этой адаптации: логическое `in_scope`, `result_origin`, `extraction_status`. Примеры значений остальных предметных полей не объявляются официальными закрытыми словарями. Направление метрики имеет рекомендуемые обозначения; нестандартное обозначение вызывает предупреждение, а не отказ по вымышленному словарю условий.

```bash
python -m pip install -r tools/requirements.txt
python tools/check_submission.py submission test --json-report report.json
python tools/check_submission.py submission_template --template
```

Коды выхода: **0** — все выполненные проверки прошли; **1** — ошибки структуры, значений или связей; **2** — нужны проверки источников/предупреждений. Отсутствие работоспособного PDF-парсера, отсутствие каталога PDF, ненайденная цитата или источник только в рисунке не маскируются кодом 0. Для пустого шаблона существует отдельный режим `--template`.

Нормализация цитат ограничена Unicode, пробелами и переносом слова через дефис на границе строк; кириллица, цифры и знаки не удаляются. Проверка буквального присутствия **не доказывает** правильность привязки числа к метрике, научную достоверность или полноту разметки. Точность/полнота извлечения рассчитываются отдельно по завершённому эталону; данный скрипт не является скорером.


Поиск цитат использует независимые извлечения pypdf и PyMuPDF: достаточно буквального совпадения в одном движке на той же странице. Тексты разных движков и разных страниц не склеиваются. Для `duplicate_of` допускается явно совместимое округление нормализованных значений разной точности; исходные записи не переписываются.


В абляциях без извлечённого контекста `top_k=0` и `metric_k=0` допустимы; номер страницы должен быть положительным.
