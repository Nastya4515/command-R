# Кейс 5. Предметная область 1 — тонкоплёночные солнечные элементы

## Что в папке

| Папка | Что в ней |
|---|---|
| `dev/` | 21 статья (`D001.pdf` … `D022.pdf`) для разработки и отладки решения |
| `dev_gold/` | Эталонная разметка этих 21 статьи в формате сдачи — образец того, как должен выглядеть результат |
| `test/` | 90 статей (`P001.pdf` … `P090.pdf`), по которым оценивается решение. Эталон к ним выдаётся только после оценки |
| `submission_template/` | Пустые таблицы формата сдачи и `README.md` с описанием полей и правил заполнения |
| `tools/check_submission.py` | Проверка набора данных перед сдачей |

Условия кейса — в опубликованном описании. Этот файл их не меняет, а только объясняет состав материалов.

## Формат сдачи

Итоговый набор данных сдаётся в виде семи таблиц из `submission_template/`. Это рекомендуемый формат: в нём результаты всех команд сравниваются с эталоном автоматически. Описание полей, словари допустимых значений и соглашения — в `submission_template/README.md`.

- `publication_id` — имя файла без расширения: `D007`, `P042`.
- В `publications.csv` строка заводится для каждой статьи, по которой сдаётся решение.
- Набор данных по `test/` — основной результат. Набор по `dev/` сдавать не обязательно.

## Как пользоваться эталоном dev

`dev_gold/` заполнен по тем же правилам, по которым размечен test. На нём удобно:
- проверить, что ваш конвейер выдаёт таблицы нужного формата;
- посчитать точность и полноту вашего извлечения до сдачи;
- посмотреть, как оформлены непростые случаи: исключённая статья (`in_scope=false` и причина), цитируемые значения (`result_origin=cited`), повторные упоминания одного значения (`duplicate_of`), неуказанный тип значения (пустой `aggregation`), значения только в supplementary (`present_not_extractable`), замечания проверки (`issues.csv`).

В эталоне записаны и дополнительные показатели (дефицит Voc, Jmpp, Vmpp, AVT и др.). При оценке извлечения учитываются только показатели из списка `metric_name` условий.

## Проверка перед сдачей

```
python -m pip install pypdf
python tools/check_submission.py ПАПКА_С_ВАШИМИ_CSV test
```

Скрипт проверяет колонки, допустимые значения, ссылки между таблицами и то, что каждая цитата `source_fragment` есть на указанной странице PDF. Пример на эталоне: `python tools/check_submission.py dev_gold dev`.

Ошибки (`ОШИБКА`) нужно исправить. Предупреждения (`внимание`) — проверить вручную: текст, извлечённый из PDF, иногда отличается от видимого (лигатуры, переносы, перемешанные колонки таблиц).
